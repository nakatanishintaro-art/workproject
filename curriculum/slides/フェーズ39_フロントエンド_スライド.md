### S04　用語ミニ講座①「フロントエンド・UI・コンポーネント」
- **フロントエンド**：利用者が直接さわる**画面側**（入力欄・一覧・ボタンなど見える部分）
- **UI（ユーザーインターフェース）**：人とアプリの“接点”。見た目と操作のこと
- **コンポーネント（部品）**：画面を「入力フォーム」「一覧」「ボタン」といった**部品の組み合わせ**で考える見方
- 今日は設計を、こうした**部品ごと**にAIへ頼んで組み上げます
> 🎤 例え：画面は「ブロックの組み立て」。フォームというブロック、一覧というブロック…と分けて作れば、直すときもそのブロックだけ触ればよい。

### S05　用語ミニ講座②「フォーム・イベント・状態（state）」
- **フォーム**：利用者が値を**入力する枠**（テキスト欄・選択・チェックなど）
- **イベント**：利用者の操作の合図。例＝「**ボタンを押した**」「**入力した**」
- **状態（state）**：今アプリが持っている**データの中身**（例：一覧に入っている件数）。操作で状態が変わり、画面に反映される
- 覚え方：**操作（イベント）→ 中身が変わる（状態）→ 画面が更新される**
> 🎤 講師ノート：この3語が今日の背骨。「押す→中身が変わる→画面に出る」という一方向の流れだけ体で掴めれば十分。

### S06　技術の基礎（ざっくり）
- 業務アプリの画面は、たいてい **入力フォーム → 一覧表示 → ボタン操作** の3点セット
- ①フォームで値を受け取る → ②一覧に並べて見せる → ③ボタンで追加・編集・削除する
- 設計（フェーズ38）の「どんな項目を、どう並べ、何ができるか」を、この3点に**割り付ける**だけ
- 難しい理屈より、**1部品ずつ作って動かす**のがエキスパートでも変わらない基本
> 🎤 「設計→部品→動作確認」を小さく回す。今日はその開発リズムを実アプリ規模でなぞる。

### S10　本編①：入力フォームを作り込む（解説）
- まず**入力フォーム**。設計の「入力項目」を画面の枠にする
- 最小構成：**入力欄（テキスト・日付・選択など）**＋**送信/追加ボタン**
- 作り込みの観点：**必要な項目がそろっているか／未入力を防ぐか（必須チェック）／押しやすいか**
- この段階では保存や一覧反映はまだ。**「値を受け取る入口」**を先に固める
> 🎤 「フォームはアプリの玄関」。設計の項目と過不足なく一致しているかをここで合わせる。

### S11　本編①：デモ（フォームをAIに作らせる）
🖥 入力例（AIコーディングツールへの依頼）：
- 「`index.html` に**日報の入力フォーム**を作って。項目は**日付・作業内容（テキスト）・作業時間（数値）**。下に**追加ボタン**」
- 「`style.css` で、業務用に見やすく整えて（藍系・余白ひろめ・ラベルは項目の上）」
- 「**作業内容が空のときは追加できない**ようにして（簡単な必須チェック）」
🖥 コードのイメージ（短い例）：
```html
<form id="reportForm">
  <label>日付 <input type="date" name="date"></label>
  <label>作業内容 <input type="text" name="task" required></label>
  <label>作業時間 <input type="number" name="hours"></label>
  <button type="submit">追加</button>
</form>
```
> 🎤 コードは読めれば十分。「項目＝設計、`required`＝必須チェック」だけ指さして確認する。

### S14　本編②：デモ（一覧表示をAIに作らせる）
🖥 入力例：
- 「フォームの下に**一覧表**を作って。列は**日付・作業内容・作業時間**。まずは**サンプル2〜3件**を表示して見た目を確認したい」
- 「`style.css` で、見出し行に薄い背景色、行の境界線、はみ出す時は横スクロールにして」
- 「一覧の上に**「全◯件」**の件数表示も付けて」
🖥 コードのイメージ（短い例）：
```html
<table id="reportList">
  <thead><tr><th>日付</th><th>作業内容</th><th>作業時間</th></tr></thead>
  <tbody><!-- ここに行が入る --></tbody>
</table>
```
> 🎤 「見出し＝設計の項目、`tbody`＝データが並ぶ場所」。空の器を先に用意する感覚を見せる。

### S16　本編③：ボタン操作をつける（解説）
- 最後に**ボタン操作**。フォームと一覧を**JavaScriptでつなぐ**＝画面が「動く」心臓部
- 基本の操作は3つ：**追加**（フォーム→一覧に1行増やす）／**削除**（行を消す）／（余力で）**編集**
- 流れは一方向：**ボタンを押す（イベント）→ データを変える（状態）→ 一覧を描き直す（表示更新）**
- AIに任せてよい。あなたは「**押したら設計どおり動くか**」を確認する係
> 🎤 「押す→中身が変わる→画面が更新される」。S05の3語がここで実際に動く。今日のハイライト。

- 「各行に**削除ボタン**を付けて、押したらその行を一覧から消して」

### S21　よくある失敗と対処
- ボタンを押しても一覧が増えない → JSが読み込まれているか確認。エラー文をそのままAIに貼って「直して」
- 一覧の列が設計とずれる → 設計の項目を再提示し「この列構成に合わせて」と依頼
- 削除で別の行が消える／全部消える → 行の指定が曖昧。「押した行だけ消えるようにして」と具体化
- AIの修正で他が壊れた → **Gitで戻す**（フェーズ29）／「さっきの状態に戻して」と頼む
> 🎤 「詰まり＝順調」。エラー文は道案内。開発者ツール（F12）のコンソールを一緒にのぞく。
