### S04　用語ミニ講座①「フロント・バックエンド・サーバー」
- **フロントエンド**：利用者が見て触る“表側”（画面・ボタン・入力欄）。フェーズ39で作った部分
- **バックエンド**：画面の裏で動く“裏側”。データを保存したり取り出したりする係
- **サーバー**：裏側の処理を動かし続けるコンピュータ（いつも起きていて、頼まれた仕事をこなす）
> 🎤 例え：飲食店で言うと、フロントは「客席とメニュー」、バックエンドは「厨房と冷蔵庫」。今日は厨房と冷蔵庫をつなぎます。

### S05　用語ミニ講座②「データベース・CRUD・API」
- **データベース（DB）**：データを整理してしまっておく“棚”。表（テーブル）の形で保存する
- **CRUD（クラッド）**：データ操作の4つの基本。**C**作成／**R**読取（一覧・検索）／**U**更新／**D**削除
- **API**：表側と裏側が話すための“受付窓口”。「保存して」「一覧ちょうだい」と頼む決まった入口
> 🎤 講師ノート：CRUDは今日ずっと出てくる合言葉。「作る・読む・直す・消す」の4つ、とだけ覚えて帰ってもらえればOK。

### S06　技術の基礎（ざっくり）
- 画面（フロント）は、**API**という窓口を通して、裏側（バックエンド）に「保存して」「一覧ちょうだい」と頼む
- 裏側は頼まれた通りに**データベース**を読み書きし、結果を画面に返す
- データは**サーバー側に残る**ので、画面を閉じても、別の人が開いても、同じデータが見える
- つき合い方：**AIに1機能ずつ書かせ→動かして確認→次へ**。一気に全部作らせない
> 🎤 「入力→窓口（API）→棚（DB）→また画面へ」。この一往復が今日の全体像です。

### S07　今日使うツール：Claude Code／Codex＋BaaS
- **Claude Code／Codex**：指示に沿ってコードを書く・直す・説明してくれるAIペアプロ相手（上級で習得済み）
- **BaaS（バース）**：Backend as a Service。裏側（DB・API・認証など）を**自前で組まず設定で使える**サービス。例：**Supabase** など
- なぜBaaS？→ サーバーの構築や運用を肩代わりしてくれるので、**今日は「つなぐ」ことに集中**できる
> ⚠️ 機能・料金・画面・無料枠は変わります。**最新の仕様は必ず各公式サイトで確認**してください。特定のサービスに固定せず、「DB・API・CRUD」という考え方を軸にします。

### S08　基本操作①：裏側の準備（プロジェクトを作る）
- ①BaaS（例：Supabase等）にログインし、**プロジェクト（＝アプリ1つ分の入れ物）**を新規作成
- ②データをしまう**テーブル（表）**を作る。今回は例として「メモ」を1つ
- ③テーブルの**列（カラム）**を決める：id（自動）／title（題名）／created_at（作成日時・自動）
🖥 画面：プロジェクト作成 → テーブル作成 → 列の追加、までを指さしで確認
> ⚠️ ここでは**ダッシュボードの管理画面**で作ります。演習は**サンプルの内容**で。実データ・個人情報は入れません。

### S09　基本操作②：AIに“つなぐコード”を書かせる準備
- 画面（フロント）から裏側に頼むには、**接続情報**（プロジェクトのURLと公開キー）を画面側に設定する
- 設定は**環境変数**（`.env`など、鍵や設定をコードに直書きせずまとめて置く場所）に入れるのが基本
- Claude Code／Codexに「この接続情報で保存できるようにして」と頼み、書いてもらう
> ⚠️ **APIキーやシークレット（秘密の鍵）は画面で読み上げない・スクショに写さない・チャットに貼らない**。研修では講師が用意した**ダミー値／サンプル**で進めます。本番の鍵は扱いません。

### S10　本編①：データを保存する（Create）（解説）
- 目標：入力欄に打った文字を、**送信ボタンで裏側に保存**する（CRUDの「C＝作成」）
- 流れ：入力→「保存して」とAPIに頼む→裏側がDBに1行足す→「保存できた」と返る
- 画面側は「保存できたら入力欄を空にする／エラーなら知らせる」だけ
> 🎤 「まず1件、消えずに残る」を最初のゴールに。ここが通れば裏側がつながった証拠です。

### S11　本編①：デモ（保存を1件）
🖥 AIへの頼み方（例・そのまま試す）：
- 「フェーズ39のフォームに、入力した題名をメモテーブルへ保存する処理を足して。保存後は入力欄を空にして」
🖥 生成されるコードのイメージ（短い例。中身は一緒に読む）：

> ⚠️ AIが書いたコードは**そのまま信じない**。何をしている行か、一緒に読んでから動かします。

### S13　本編②：一覧で読み取る（Read）（解説）
- 目標：保存したデータを**取り出して画面に一覧表示**する（CRUDの「R＝読取」）
- 流れ：画面が開く→「一覧ちょうだい」とAPIに頼む→裏側がDBから全行を返す→画面に並べる
- 新しい順に並べる、といった**並び替え**もAPIに頼める
> 🎤 「保存（C）」と「一覧（R）」がつながると、**入力→保存→一覧表示**という今日の主目的が完成します。

### S14　本編②：デモ（一覧表示）
🖥 AIへの頼み方（例）：
- 「メモテーブルの全件を新しい順で取得して、画面に一覧で表示して」
🖥 生成されるコードのイメージ（短い例）：
```js
// 「メモ」を新しい順に全件取り出す
const { data } = await db
  .from("memo")
  .select("*")
  .order("created_at", { ascending: false });
```
> 🎤 `select("*")`＝「全部の列をちょうだい」、`order`＝「並び順の指定」。上級で学んだSQLの考え方が、そのまま実アプリで生きています。

### S16　本編③：更新と削除（Update／Delete）（解説）
- **更新（U）**：既にある1件を選んで、内容を書き換える（例：題名を直す）
- **削除（D）**：いらない1件を消す
- どちらも「**どの行か**」を`id`（各行に付く番号）で指定して頼むのがポイント
> ⚠️ 削除は元に戻せないことが多い。**サンプルデータで練習**し、消す前に「本当に消す？」の確認を入れるのが安全。

### S17　本編③：デモ（更新・削除）
🖥 AIへの頼み方（例）：
- 「一覧の各行に『削除』ボタンを付けて、そのidの行を消せるようにして」
🖥 生成されるコードのイメージ（短い例）：
```js
// idで指定した1件を消す
await db.from("memo").delete().eq("id", targetId);
// idで指定した1件の題名を書き換える（更新）
await db.from("memo").update({ title: newTitle }).eq("id", targetId);
```
> 🎤 `eq("id", …)`＝「idがこれと等しい行だけ」。“どの行か”を必ず指定するのがCRUDの基本作法です。

### S18　ハンズオン③：更新・削除を足そう（20分）

- 課題：サンプルのメモで**削除**を1回、できれば**更新**も1回試す
- 成果物：**CRUD動作メモ**（作成・読取・更新・削除のうち、どこまで動いたかを○×で記録）
> 🎤 講師ノート：全部そろわなくてOK。「C（保存）とR（一覧）」が通っていれば今日の主目的は達成。U・Dは発展。

### S21　よくある失敗と対処
- 保存できない → まず**エラーメッセージ**を確認。そのままAIに貼って直させる（※鍵は含めない）
- 一覧が空 → テーブル名・列名のスペルちがい／並び替え指定ミスを疑う。1件手で足して表示を試す
- 接続エラー → 接続情報（URL・公開キー）の設定場所と綴りを確認。環境変数の読み込み漏れが定番
- AIのコードが動かない → 「どの行で何のエラーか」を伝えて**1機能ずつ**直す。一度に直させない
> 🎤 「エラーは敵ではなく手がかり」。メッセージを読む習慣がエキスパートへの近道。
