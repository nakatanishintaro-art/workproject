### S04　用語ミニ講座①「バージョン管理・リポジトリ・コミット」
- **バージョン管理**：ファイルの**変更履歴を記録し、いつでも前に戻せる**仕組み
- **リポジトリ（repository）**：変更履歴をためておく**入れもの（＝管理された作業フォルダ）**
- **コミット（commit）**：その時点の状態に**名前をつけて記録する**こと（＝セーブポイント）
> 🎤 例え：ゲームの「セーブ」。コミットするたびにセーブが増え、いつでもそのセーブに戻れる。リポジトリはセーブデータの入った箱。

### S05　用語ミニ講座②「プッシュ・プル・GitHub・公開/非公開」
- **GitHub**：リポジトリを**クラウドに預けて共有できる**サービス（Gitの保管場所）
- **プッシュ（push）**：手元の記録を**GitHubへ送って保存**する
- **プル（pull）**：GitHubの最新を**手元へ取り込む**
- **公開（Public）／非公開（Private）**：誰でも見られる／自分（と許可した人）だけ
> 🎤 講師ノート：今日は「聞いたことがある」状態でOK。特に **公開/非公開の違い** と **プッシュ＝クラウドに保存** の2つは覚えて帰ってもらう。

### S06　技術の基礎（ざっくり）
- Gitは変更を**「スナップショット（その時点の写真）」**として重ねて保存する
- だから **元に戻せる**（前の写真に戻る）／**何を変えたか**が後から分かる
- 手元（自分のPC）とクラウド（GitHub）の**2か所**にデータが持てる＝安全
- つき合い方＝「**きりのいいところでコミット、区切りでプッシュ**」
> 🎤 「保存し忘れて泣く」がなくなる道具。難しく考えず“こまめにセーブ”の感覚で。

### S07　今日使うツール：Git・GitHub・VS Code

- **GitHub**：その履歴をクラウドに置いて共有するサービス
- **VS Code**：文章やコードを書くエディタ。**ボタン操作でGitを使える**（コマンド少なめでOK）
- **AIの助け**：エラーの意味や次の操作を、AIに聞きながら進められる

### S10　本編①：コミット＝変更を記録する（解説）
- 流れは3ステップ：**①変える → ②選ぶ（add）→ ③記録する（commit）**
- **add（ステージ）**：記録したい変更を「これを保存します」とかごに入れるイメージ
- **commit**：かごの中身に**ひとことメモ（メッセージ）**をつけて保存
- メモは「何をしたか」を短く（例：`はじめてのファイルを追加`）
> 🎤 「変えた→かごに入れた→名前をつけて保存」。この3つがコミットの正体。

### S11　本編①：デモ（はじめてのコミット）
🖥 例（短いコマンド・そのまま試す）：
```
git add .
git commit -m "はじめてのコミット"
```
- `git add .` ＝この変更を全部かごに入れる
- `-m "..."` ＝コミットのメモ（日本語でOK）
> 🎤 打つ→Enter→「1 file changed」等が出るのを一緒に確認。VS Codeの✓ボタンでも同じ、と見せる。

### S12　ハンズオン①：コミットしてみよう（20分）
- 手順：①作業フォルダに小さなファイルを1つ作る（例：`memo.txt`）→②`git add .`→③`git commit -m "メモを追加"`
- 課題：ファイルを少し書き換えて、**もう1回コミット**（合計2回）
- 成果物：**操作チェックリスト**（init／add／commit×2 ✔）
> 🎤 講師ノート：手が止まる人にはS11の例文をそのままコピーさせる。エラーは「AIに貼って意味を聞く」を実演。

### S13　本編②：GitHubに保存する（解説）
- 手元のコミットは、まだ**自分のPCの中だけ**
- **GitHubに置き場所（リモート）を用意 → プッシュ**でクラウドに保存
- こうすると **PCが壊れても安心**／**他の人と共有**もできる
- 置き場所を作るとき、**公開（Public）か非公開（Private）を選ぶ**
> ⚠️ 迷ったら **非公開（Private）** を選ぶ。あとで公開に変えられる。

### S14　本編②：デモ（GitHubへプッシュ）
🖥 例：GitHubで空のリポジトリを1つ作る → 手元とつなぐ → プッシュ
```
git remote add origin <GitHubのURL>
git push -u origin main
```
- `remote add origin` ＝クラウドの置き場所を登録
- `push` ＝送って保存（初回だけ `-u origin main`）
> 🎤 GitHub画面に自分のファイルが現れる瞬間を見せる。「これでクラウドに保存できた」を体感させる。

### S15　ハンズオン②：GitHubに保存しよう（20分）
- 手順：①GitHubで**非公開（Private）**の空リポジトリを作る→②手順書のコマンドで手元とつなぐ→③プッシュ→④GitHubの画面で確認
- 課題：さらにファイルを1つ変えて、`add`→`commit`→`push` をもう1周
- 成果物：**操作チェックリスト（続き）**（リポジトリ作成／push／GitHubで確認 ✔）
> ⚠️ 演習は**サンプル・架空の内容**で。実データ・機密は入れない。

### S16　本編③：元に戻す・履歴を見る・プル（解説）
- **履歴を見る**：これまでのコミット（セーブ）を一覧で確認できる
- **元に戻す**：前のコミットの状態に戻せる（＝失敗しても取り返せる）
- **プル**：GitHub側の最新を手元に取り込む（別のPCや共同作業のとき）
> 🎤 「戻せる」が今日いちばんの安心材料。“こわくてもコミットしておけば取り返せる”。

### S17　本編③：デモ（履歴・戻す・プル）
🖥 例（短いコマンド）：
```
git log --oneline
git pull
```
- `git log --oneline` ＝コミットの一覧を1行ずつ表示
- 「前の状態に戻したい」ときは、**戻し方をAIに聞きながら**慎重に行う
> 🎤 履歴に自分のメモ（コミットメッセージ）が並ぶのを見せ、「メモを丁寧に書くと後で助かる」と伝える。

### S18　ハンズオン③：履歴を見て・戻してみよう（15分）
- 手順：①`git log --oneline` で履歴を見る→②ファイルをわざと書き換える→③講師と一緒に**前の状態に戻す**を体験
- 課題：履歴に自分のコミットが2つ以上並んでいることを確認
- 成果物：**操作チェックリスト（履歴確認／戻す体験 ✔）**
> ⚠️ 「戻す」操作は種類が多い。今日は**講師ガイド付き**で1つだけ体験。深追いしない。

### S19　追加の便利機能：README・.gitignore・公開範囲
- **README（リードミー）**：リポジトリの「表紙・説明書」。何のプロジェクトか書く
- **.gitignore**：**GitHubに上げたくないファイルを除外**する設定（後述の機密対策に重要）
- **公開範囲**：Public（誰でも閲覧）／Private（自分と許可した人だけ）はいつでも見直せる
> 🎤 「READMEは自分への説明にもなる。半年後の自分が助かる」。

### S20　ミニ演習：READMEと.gitignoreを置く（10分）
- 手順：①`README.md` を作り、プロジェクト名と一言説明を書く→②`.gitignore` に上げたくないもの（例：`.env`、パスワードのメモ）を書く→③`add`→`commit`→`push`
🖥 `.gitignore` の例：
```
.env
secret.txt
```
> ⚠️ **.gitignore に書いても、すでにプッシュ済みのものは消えない**。最初から上げないのが安全。

### S21　よくある失敗と対処
- コマンドでエラー → **メッセージをAIに貼って意味を聞く**／VS Codeのボタン操作に切り替える
- `push` が拒否される → まず `git pull` で最新を取り込み、もう一度 `push`
- 何をコミットしたか不安 → `git status` と `git log --oneline` で今の状態を確認
- 間違えて保存した → あわてず講師へ。**コミットしてあれば取り返せる**
> 🎤 「うまくいかない＝故障ではない」。エラー文はヒント。AIと講師が味方。

### S22　安全・情報管理の注意（最重要）
- **GitHubに上げてはいけない**：APIキー・パスワード、個人情報（氏名・住所等）、取引先の機密・社外秘
- 公開範囲は**必ず確認**。迷ったら **非公開（Private）**
- 秘密の情報は `.env` などに分け、**.gitignoreで最初から除外**
- **一度Publicに上げた情報は拡散し得る**。消しても手遅れなことがある
> 🎤 講師ノート：ここは今日必ず持ち帰る。演習は**サンプル・架空の内容**で。実際のキーや顧客情報は絶対に使わない。
