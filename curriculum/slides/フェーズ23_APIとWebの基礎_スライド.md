### S04　用語ミニ講座①「Web・ブラウザ・サーバー」
- **Web（ウェブ）**：世界中のコンピュータをつないで、ページや情報を見られる仕組み
- **ブラウザ**：ホームページを見るためのソフト（Edge・Chrome・Safariなど）。**あなたの手元**の道具
- **サーバー**：情報を保管して、頼まれたら渡す**相手側**のコンピュータ
- つまりWebは「**手元のブラウザ**」が「**遠くのサーバー**」に頼んで情報を受け取る仕組み
> 🎤 例え：ブラウザ＝あなた、サーバー＝図書館の司書。「あの本ください」と頼むと出してくれる。

### S05　用語ミニ講座②「HTTP・JSON・API」
- **HTTP**：ブラウザとサーバーが会話するときの**共通ルール（言葉づかい）**。「これください」「はい、どうぞ」の約束事
- **JSON（ジェイソン）**：コンピュータ同士が**データを受け渡すときの書き方**。人にも少し読める整った箇条書きのような形式
- **API（エーピーアイ）**：あるアプリが別のアプリに用意した「**データをやり取りする窓口**」
- 今日はこの3つを「聞いたことがある→なんとなく分かる」にします
> 🎤 講師ノート：今は暗記不要。あとで実物を画面で見せる。「HTTP＝ルール、JSON＝データの形、API＝窓口」の3語だけ持ち帰ってもらう。

### S06　技術の基礎（ざっくり）：Webは「頼む→返す」の繰り返し
- ホームページを見るとき、裏では**毎回**この流れが起きている
  - ①ブラウザが「このページください」とサーバーに**お願い（リクエスト）**
  - ②サーバーが中身を用意して**返事（レスポンス）**
  - ③ブラウザが受け取って**画面に表示**
- 天気アプリも、地図も、通販も、基本はこの「頼む→返す」の積み重ね
> 🎤 「難しそうなアプリも、分解すると“お願いと返事”の繰り返し」。ここが今日の土台。

### S07　今日使う道具：ブラウザの開発者ツール（F12）
- **開発者ツール**：ブラウザに最初から入っている、**裏側の通信をのぞく画面**
- キーボードの **F12**（または右クリック→「検証」）で開く。**インストール不要・無料**
- 今日は主に「**ネットワーク**」というタブを使い、頼む→返すの様子を見るだけ
- **見るだけ**なので、押しても壊れません。閉じれば元通り
> ⚠️ ブラウザの種類・バージョンで名称や配置が少し違います。**最新の画面は公式のヘルプで確認**してください。

### S08　基本操作①：開発者ツールを開いてみる
- ①いつものブラウザで、当たり障りのない公開ページを開く（例：公共機関の公開ページ）
- ②**F12**を押す→画面の横か下に、英語まじりのパネルが出る
- ③上の並びから「**ネットワーク（Network）**」を選ぶ
- ④一度ページを再読み込み（F5）すると、通信の一覧がズラッと出る
🖥 画面：F12でパネルが開く→「Network」タブ→再読み込みで一覧が流れる様子を実演
> 🎤 講師ノート：最初は文字が多くて驚く。「全部分からなくてOK。今から見る所だけ一緒に探す」と安心させる。

### S09　基本操作②：一覧の「1行」をのぞく
- ネットワークの一覧は「**ブラウザが送ったお願い**」が1行ずつ並んでいる
- どれか1行をクリックすると、右側に詳しい中身が出る
  - **Status（ステータス）**：うまくいったかの番号（例：200＝成功）
  - **Headers（ヘッダー）**：やり取りの付帯情報
  - **Response（レスポンス）**：返ってきた中身
🖥 画面：1行クリック→Status/Headers/Response を順に指さしで確認
> 🎤 「メールでいう“送信済みトレイ”。何を頼んで何が返ったかが全部残っている」。

### S10　本編①：解説「ブラウザとサーバーのやり取り」
- 1ページ見るだけでも、裏では**何十回**も「頼む→返す」が起きている
  - 文字・画像・デザイン・ボタンの動き…それぞれを別々にお願いしている
- だから通信一覧は**行がたくさん**になる（＝正常なこと）
- ページが遅い・崩れるときは、この一覧のどこかで**返事が失敗**していることが多い
> 🎤 「ホームページは“一枚の紙”ではなく、たくさんの部品を集めて組み立てている」とイメージづけ。

### S13　本編②：解説「HTTPとJSON」
- **HTTP**＝頼む→返すの**共通ルール**。世界中のWebが同じルールなので、どの端末でもつながる
- 返事のときの番号（ステータス）にも意味がある
  - **200**：成功　／　**404**：見つからない　／　**500**：サーバー側の不具合
- **JSON**＝データを受け渡すときの**整った書き方**。「名前：値」の組を並べた形で、機械にも人にも扱いやすい
> 🎤 「404 Not Found」は皆さんも見たことがあるはず。あれがHTTPの返事の一種、と結びつける。

### S14　本編②：デモ「JSONを実際に見る」
🖥 実演：
- **JSONをそのまま返す公開ページ（データ配布用のURL）**をブラウザで開く
- 画面いっぱいに「{ }」や「"名前": "値"」が並ぶ様子を見せる
- 「これはデザインのない“データそのもの”」「人が読む用ではなく、アプリが読む用」と説明
🖥 JSONの読み方イメージ（サンプル・架空）：
```
{
  "天気": "晴れ",
  "気温": 28,
  "場所": "サンプル市"
}
```
> 🎤 「ホームページの見た目を全部はがすと、中身はこういうデータ。これがJSON」。

### S16　本編③：解説「APIとは何か」
- **API＝アプリ同士がデータをやり取りする“窓口”**
- 例：天気アプリは、気象データを持つ**別のサービスのAPI**に「今日の天気ください」と頼み、JSONで受け取って表示している
- あなたのアプリが**自分で全部のデータを持たなくても**、他所の窓口から借りられる
- 「頼む→返す（HTTP）」で「データ（JSON）」を受け取る、その**窓口がAPI**
> 🎤 例え：APIは店の「注文カウンター」。決まった頼み方をすれば、決まった形で商品（データ）が返ってくる。

### S17　本編③：デモ「身近なアプリの裏にAPIがある」
🖥 実演・説明：

- 「1つのアプリが、実はいくつもの窓口（API）からデータを借りて成り立っている」と図で示す
- ⚠️ 具体サービス名は例示にとどめ、**実在サービスの仕様は各公式で確認**と添える
> 🎤 「便利なアプリほど、裏でたくさんのAPIを上手に組み合わせている」。

### S19　追加で知る：APIカタログと「公開API」

- 上級・エキスパートでは、この窓口に**プログラムから**お願いして、自分のアプリにデータを取り込む
