### S04　用語ミニ講座①「データベース・テーブル・SQL」
- **データベース（DB）**：決まった形でデータをためて、探しやすくした“整理された台帳のしくみ”（中級16の復習）
- **テーブル（表）**：1種類のデータを集めた表。縦の列＝**カラム（項目）**、横の行＝**レコード（1件）**
- **SQL（エスキューエル）**：データベースに「入れて」「探して」「直して」と**命令する専用の言葉**
> 🎤 例え：テーブル＝Excelの1枚のシート。SQL＝そのシートに「この条件で抜き出して」と頼む“お願いの文”。プロンプトのDB版だと思えば怖くない。

### S05　用語ミニ講座②「CRUD・WHERE・クエリ」
- **CRUD（クラッド）**：データ操作の基本4つの頭文字
  - **C**＝INSERT（登録）／**R**＝SELECT（検索）／**U**＝UPDATE（更新）／**D**＝DELETE（削除）
- **WHERE（ウェア）**：「どのデータに対して？」を決める**条件の絞り込み**（例：価格が500円以上のものだけ）
- **クエリ**：データベースへの1つの問い合わせ（＝1本のSQL文）のこと
> 🎤 講師ノート：今日覚えて帰るのは「**CRUD＝入れる・探す・直す・消す**」と「**WHERE＝どれに対してか**」の2つだけ。あとはAIが手伝います。

### S06　技術の基礎（ざっくり）
- SQLは、ふつうの言葉に近い**短い命令文**。`SELECT ... FROM ... WHERE ...`のように“ほぼ英語の語順”で読める
- データベースは世界共通で、SQLは**多くのDBで通じる共通語**（一度覚えると応用が利く）
- 今日は**SQLite（エスキューライト）**という、インストール不要でも試せる**軽くて手軽なDB**を使う
- 大事な心得＝**UPDATE・DELETEには必ずWHERE**（条件を付け忘れると全件に効いてしまう）
> 🎤 「英語の命令文をちょっと書くだけ」。身構えず、まずAIに書かせて、一緒に読むところから始めます。

### S10　本編①：かんたんなテーブル設計とCREATE（解説）
- テーブルを作る命令＝**CREATE TABLE**。「表の名前」と「カラム（項目）と型」を決める
- **型（かた）**：そのカラムに入るデータの種類。今日は2つだけ→**数値（INTEGER）／文字（TEXT）**
- 設計のコツ（中級16の復習）：各行を見分ける**背番号（id）**を1つ用意する
- 難しく考えず「**何の表か・どんな項目か・背番号は何か**」の3点を決めるだけ
> 🎤 「設計図（中級16）を、そのままCREATE文にするだけ」。項目名と型を並べれば表ができる、と安心させる。

### S11　本編①：デモ（サンプル「商品テーブル」を作る）
🖥 例（そのまま実行・架空データ用の空テーブル）：
```sql
-- 商品テーブルを作る（id=背番号／name=品名／price=価格／stock=在庫数）
CREATE TABLE products (
  id     INTEGER,   -- 背番号（数値）

  price  INTEGER,   -- 価格（数値）

```
- `products`が表の名前。`( )`の中がカラム。`--`から後ろは**コメント（人間へのメモ）**で実行に影響しない
> 🖥 実行すると「空の商品テーブル」ができる。まだ中身は0件。次でデータを入れる。

### S13　本編②：データを入れる・探す（解説）
- **INSERT（登録）**：`INSERT INTO 表名 (...) VALUES (...);` で1件ずつ行を追加
- **SELECT（検索）**：`SELECT 項目 FROM 表名;` で取り出す。`*`は「全部の項目」の意味
- **WHERE（絞り込み）**：`SELECT ... WHERE 条件;` で「条件に合う行だけ」に絞る（例：`price >= 500`）
- まず全部入れて、次に**必要な分だけ探す**—これがデータ活用のいちばんの基本
> 🎤 「入れる(INSERT)」と「探す(SELECT)」が使えれば、もうデータベースを触れています。WHEREは“絞り込みの魔法の言葉”。

### S14　本編②：デモ（INSERT／SELECT／WHERE）
🖥 例（架空データ・そのまま実行）：
```sql
-- 3件を登録する
INSERT INTO products VALUES (1, 'ペンA', 120, 50);
INSERT INTO products VALUES (2, 'ノートB', 300, 20);
INSERT INTO products VALUES (3, 'カバンC', 1500, 5);

-- 全部を見る
SELECT * FROM products;

-- 価格が500円以上のものだけ、品名と価格を見る
SELECT name, price FROM products WHERE price >= 500;
```
- 最後のSELECTの結果は「カバンC・1500」だけ。**WHEREで1件に絞れた**ことを画面で確認
> 🎤 全件→絞り込みの順で実行し、「WHEREを足すと結果が減る」様子を体感させる。文字は`' '`で囲むことも指さしで確認。

### S15　ハンズオン②：データを入れて検索しよう（25分）
- 手順：①S14のINSERTで架空データを3件入れる→②`SELECT * FROM products;`で全件表示→③WHEREで「価格が○○以上」など条件を1つ付けて絞る
- 課題：**条件を変えたSELECTを2種類**作る（例：`stock <= 10`＝在庫が少ない／`price < 200`＝安いもの）。うまく書けなければ**AIに書かせて、読んで確かめる**
- 成果物：**INSERT一式＋SELECT（絞り込み）2本**（実行して結果が出たか ✔）
> 🎤 講師ノート：`>= <= <` の記号はAIに聞けばOK。「自分で条件を1つ思いついて絞れた」を達成ラインに。

### S16　本編③：データを直す・消す（解説）
- **UPDATE（更新）**：`UPDATE 表名 SET 項目=値 WHERE 条件;` で、条件に合う行の値を書き換える
- **DELETE（削除）**：`DELETE FROM 表名 WHERE 条件;` で、条件に合う行を消す
- **最重要**：UPDATE・DELETEに**WHEREを付け忘れると、全部の行**が書き換わる・消える
- 直す前・消す前に、まず**同じ条件のSELECTで対象を確認**する癖をつけると安全
> 🎤 講師ノート：ここが今日の“事故りやすい所”。「**まずSELECTで対象を見る→それからUPDATE/DELETE**」を全員に徹底する。

### S17　本編③：デモ（UPDATE／DELETE）
🖥 例（架空データ・WHEREを必ず付ける）：
```sql
-- ①先に対象を確認（id=2 の行だけ？）
SELECT * FROM products WHERE id = 2;

-- ②在庫を 20 → 8 に更新
UPDATE products SET stock = 8 WHERE id = 2;

-- ③id=3 の行を1件だけ削除
DELETE FROM products WHERE id = 3;
```
- WHEREがあるから、**その1件だけ**に効く。`WHERE id = 2`を消すと全件が対象になる危険を口頭で強調
> 🖥 更新後にもう一度`SELECT * FROM products;`で結果を見せ、「1件だけ変わった／消えた」を確認する。

### S18　ハンズオン③：直す・消すを安全に試そう（20分）
- 手順：①`SELECT`で対象を確認→②`UPDATE`で1件の値を書き換える→③`DELETE`で1件だけ消す→④最後に全件表示して結果を確かめる
- 課題：**必ずWHEREを付けて**、狙った1件だけを更新・削除する。消しすぎたら**INSERTで入れ直す**（サンプルなのでやり直し自由）
- 成果物：**UPDATE1本・DELETE1本（どちらもWHERE付き）**と、前後のSELECT結果メモ
> 🎤 講師ノート：わざと「WHEREを外すと全件が対象になる」を講師画面だけで見せ、怖さを共有（受講者データでは実行させない）。

### S19　追加で知る：AIにSQLを直させる・説明させる

### S21　よくある失敗と対処
- **UPDATE／DELETEでWHEREを忘れる** → 全件に効いて事故。**必ず先にSELECTで対象を確認**してから実行
- **文字を`' '`で囲み忘れる**（例：`name = ペンA`）→ 文字は`'ペンA'`のように**シングルクォートで囲む**
- **文末の`;`（セミコロン）忘れ** → 1本のSQLの終わりに`;`を付ける
- **綴り・大文字小文字の打ち間違い**（SELCT等）→ **エラー文ごとAIに貼って**直してもらう
> 🎤 「エラーは故障ではなく、DBからの“ここが違うよ”のメモ」。落ち着いてAIと直せば必ず動く、と安心させる。

### S22　安全・情報管理の注意（最重要）

- **UPDATE／DELETEは取り返しがつかない操作**。本番データでは、**先にバックアップ（コピー）**を取ってから
- 迷ったら「まずSELECTで確認」「WHEREを必ず付ける」「サンプルで試す」

### S23　業種応用：建設
- 使いどころ（サンプル）：点検テーブルから「未完了の点検だけ」を`WHERE`で抜き出す
- 例（架空）：`SELECT * FROM inspections WHERE status = '未完了';` ／完了したら`UPDATE ... SET status='完了' WHERE id=○;`
> 🖥 現場名・個人名は伏せ、**背番号(id)と状態(status)だけ**で操作する形を練習。実際の点検データは入れない。

### S24　業種応用：製造
- 使いどころ（サンプル）：在庫テーブルから「在庫が少ない品だけ」を`WHERE`で抽出（発注の目安）
- 例（架空）：`SELECT name, stock FROM products WHERE stock <= 10;` ／入荷したら`UPDATE products SET stock=50 WHERE id=○;`
> 🖥 型番・図面・社外秘は入れず、**品名は一般名・数量は架空**で。「少ない在庫を絞り込む」感覚だけをつかむ。

### S25　業種応用：サービス

- 例（架空）：`SELECT * FROM bookings WHERE date = '2026-08-06';` ／キャンセルは`DELETE FROM bookings WHERE id=○;`（先にSELECTで確認）
> 🖥 実在の顧客名・連絡先は入れない。**背番号と日付だけ**で、絞り込み・削除の練習をする。
