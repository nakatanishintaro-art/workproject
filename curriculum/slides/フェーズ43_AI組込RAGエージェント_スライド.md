### S04　用語ミニ講座①「RAG・チャンク・ベクトル検索」
- **RAG（検索を伴う生成）**：AIが**まず自社資料を探し**、その中身を根拠に答える仕組み（中級21で体験したNotebookLMの中身）
- **チャンク（分割の断片）**：長い資料を**小さく区切った一片**。資料まるごとではなく、関係する一片だけをAIに渡すための単位
- **ベクトル検索（意味で探す検索）**：言葉が違っても**意味が近い**チャンクを見つける検索。「有給」で聞いても「年次休暇」の一片を拾える
> 🎤 例え：分厚いマニュアルから「関係する数ページ」に付箋を貼り、その付箋のページだけAIに見せて答えさせる。全部読ませないのがコツ。

### S05　用語ミニ講座②「エージェント・ツール・MCP」
- **AIエージェント**：目標を渡すと、**手順を自分で考えて複数の作業を順に実行する**AI（例：調べる→まとめる→保存する、を続けてこなす）
- **ツール（道具）**：AIが呼び出して使える外部機能（検索する・計算する・ファイルを読む・APIを叩く等）
- **MCP（Model Context Protocol）**：AIエージェントを**外部のツールやデータに安全につなぐ共通の仕組み**。つなぎ方の“共通コンセント”のようなもの
> 🎤 講師ノート：RAG＝「資料を見て答える」、エージェント＝「手順を考えて動く」、MCP＝「外部に安全につなぐ」。この3語の役割の違いだけ持ち帰ってもらう。

### S06　技術の基礎（ざっくり）：RAGは3ステップ
- ①**分割（インデックス作り）**：資料をチャンクに区切り、あとで探せる形にしておく（＝下ごしらえ、事前に1回）
- ②**検索**：利用者の質問に**関係するチャンクを数個だけ取り出す**
- ③**生成**：取り出したチャンクを**質問と一緒にLLMへ渡し**、その根拠で答えさせる
- 中級21では①②をツール（NotebookLM）任せにしていた。今日は**この流れを自分のコードで組む**
> 🎤 「渡した資料の中で答えて」とLLMに頼むのが核心。①②で“渡す材料”を用意し、③で答えさせる。フェーズ42のAPI呼び出しが、ここで③に効いてくる。

- **LLM API**：フェーズ42で使った、アプリからAIを呼び出す窓口。RAGの③「生成」で使う
- 進め方は上級・42と同じ：**やりたいことを日本語で伝える → 出たコードを確認 → 動かす → 直す**
- 補助として**VS Code**（コードを見る・保存）と**ブラウザ／ターミナル**（動作確認）

### S09　基本操作②：RAGを頼むときの伝え方
- **やりたいことを日本語で**：「`data/`の資料を分割して検索できるようにし、質問に関係する部分だけをLLMに渡して答えさせたい」
- **小さく頼む**：一度に全部でなく「まず分割」「次に検索」「最後に生成」と**段階ごと**に
- **確認する**：各段階の途中結果（分割数・検索で拾えた一片）を**目で見て**から次へ進む
- コツ：**「渡した資料にないことは答えないで」**をLLMへの指示に必ず入れてもらう
> 🎤 講師ノート：「大きく頼むと大きく崩れる」。RAGも分割→検索→生成に分けて1つずつ動かす、を今日も合言葉に。

### S10　本編①：RAGの実装（解説）
- 中級21では「読み込ませて聞く」をツール任せにしていた。今日は**3ステップをコードで**組む
- **①分割**：資料を数百字ごとのチャンクに区切る（見出し単位でもよい）
- **②検索**：質問に近いチャンクを**数個**取り出す（まずは簡単なキーワード一致でも可、発展でベクトル検索）
- **③生成**：取り出したチャンクを**質問文と一緒にLLMへ渡す**（フェーズ42のAPI呼び出し）
> 🎤 「探して・渡して・答えさせる」。難しい理屈より、材料をそろえてLLMに渡す一連を体で掴む。

### S11　本編①：デモ（RAGをAIに実装させる）
🖥 入力例（AIコーディングツールへの依頼）：
- 「`data/`のテキストを**400字くらいのチャンクに分割**する関数を作って」
- 「質問文に**近いチャンクを3件取り出す**簡単な検索を付けて（まずはキーワード一致でOK）」
- 「取り出した3件を**質問と一緒にLLMへ渡し**、その内容だけを根拠に答えさせて」
🖥 コードのイメージ（短い例・流れが分かればOK）：
```python
chunks = split_text(load("data/manual.txt"), size=400)   # ①分割
hits = search(chunks, question, top_k=3)                  # ②検索（近い3件）
prompt = f"次の資料だけを根拠に答えて。資料にないことは『資料にありません』と言って。\n資料:\n{hits}\n質問:{question}"
answer = call_llm(prompt)                                  # ③生成（42のAPI）
```
> 🎤 コードは読めれば十分。「①分割 ②近い3件を検索 ③質問と一緒に渡す」の3行だけ指さす。42で書いた`call_llm`がそのまま③に効く。

### S13　本編②：AIエージェントの基礎（解説）
- **エージェント**＝目標を渡すと、**手順を自分で考えて複数の作業を順に実行する**AI

- 仕組みのイメージ：AIが「次に何をするか（どのツールを使うか）」を考え→実行→結果を見て→また考える、を**繰り返す**
- 便利だが**暴走・止まらない・余計な操作**のリスクもある。**できることを絞り、人が確認**が原則
> 🎤 「1回答えて終わり」がRAG、「手順を考えて動き続ける」がエージェント。強力だからこそ、範囲を絞って使う。

### S16　本編③：MCPで外部に安全につなぐ（解説）
- **MCP（Model Context Protocol）**：エージェントを**外部のツール・データに安全につなぐ共通の仕組み**（つなぎ方の“共通コンセント”）
- なぜ必要：つなぎ先ごとに独自実装するのは大変。MCPなら**共通の作法**で、資料・DB・社内ツールにつなげる
- 安全面の要：**何につなぐか（範囲）／読み取りだけか書き込みも許すか（権限）／認証**を明示して絞る
- 今日は**「こういう仕組みがある」を知り、読み取り専用で1つつなぐ**まで。本格運用は先の段階
> 🎤 「エージェントに外部の目と手を与えるのがMCP。だからこそ“どこまで許すか”を先に決める」。便利さと安全はセット。

🖥 確認：MCPでつないだ資料をエージェントが参照→RAGと同じく**根拠のある答え**が返る様子を実演

### S21　よくある失敗と対処
- 検索で関係ない一片が出る → チャンクの**大きさ・件数**を調整／キーワードだけでなく意味検索（ベクトル）をAIに提案させる
- 資料にないのに答えを作る → プロンプトに「**渡した資料だけを根拠に。無ければ資料にありませんと言う**」を明記
- エージェントが止まらない／余計な操作をする → 使える**ツールを絞る**・**回数の上限**を付ける・人が途中で止める
- APIエラー・料金が心配 → キーの設定・モデル名を確認（42）／**呼び出し回数を絞り**サンプルで検証（S22・46）
> 🎤 「詰まり＝順調」。エラー文はそのままAIに貼って直させる。特にエージェントは“できることを絞る”が最大の対処。

### S22　安全・情報管理の注意（最重要）
- **⚠️ APIキー・機密はコードや依頼文に貼らない**。キーは`.env`などコード外に置き、リポジトリに含めない（42の作法を継続）
- **社外にデータを出す範囲に注意**：RAGでLLMに渡す資料・エージェントの外部送信は、**どこへ何が出るか**を必ず把握。サンプル・架空のみ使用
- **エージェントの権限は最小に**：削除・外部送信・広い書き込みは既定で禁止。MCPは**読み取り専用・範囲限定**から
- AIの答えは**鵜呑みにしない**。数字・金額・法令・安全手順は**人が原本で確認**（誤答は人で止める）
> 🎤 講師ノート：必ず持ち帰り。「APIキー・機密は貼らない」「社外に出す範囲を把握」「エージェント権限は最小」「生成物は人が確認」の4点を強調。
